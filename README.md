### 💡 为什么需要它？

普通 AI 是“合意机器”，无论你提多么脱离实际的点子，它都能帮你洋洋洒洒润色出几千字可行性报告，哄你开心撞南墙。  
**驳真不替你拍板，它是你的“职业拳击陪练”：在安全环境下拼尽全力向你挥拳，帮你找出方案中最脆弱的下巴。**

| 你的想法 | 普通 AI (盲目附和) | 驳真审查 (蓝军压力测试) |
|---|---|---|
| *“工具里加个打卡积分系统提日活”* | “很好的想法，积分能增加粘性，建议设计每日签到……” | **建议放弃**。不做这功能用户用得好好的；加了老用户嫌烦；引来的全是不花钱的羊毛党。<br/>*💡 更省钱做法：直接在设置里安静显示使用天数，先看有没有人在意。* |
| *“统考防作弊一年用两次，太贵了砍掉”* | “确实，按使用频率看投入产出比不高……” | **建议保留**。这事按出一次事的代价算。考场舞弊会被撤销资质罚款，不能因为低频就砍。<br/>*💡 更省钱做法：按考试场次租用设备，无需买断。* |
| *“输入框加个前端实时格式校验”* | “建议慎重，可能会增加用户操作负担……” | **大方通过 (PASS)**。已有真实报错日志支撑，交互成熟，万一做砸了 5 分钟就能无损回滚。<br/>*好想法大大方方放行，绝不为了显摆深刻而无病呻吟。* |

## 🔍 帮你看清的三大现实

不搞复杂的理论黑话，只帮你看清真实业务的三件事：

1. 🏢 **看谁吃亏 (组织阻力)**：方案到底给谁多添了麻烦？谁在背锅？大家会不会表面配合、私底下应付糊弄差事？
2. 🔪 **看不做行不行 (功能必要)**：不做这个功能业务真的会卡死吗？做烂了几天能恢复原样？等多久能看到真实信号？
3. ⚖️ **看会不会出大事 (合规红线)**：单次出错代价自己能不能扛？依据是法律白纸黑字（【条文原文】），还是平时的通融习惯（【实务惯例】）？
   - *（注：遇到前所未见的新交互或新赛道，启动【创新沙盒】，不因缺乏过往数据盲目打死，给出 1/10 成本验证闭环）。*

## 🛑 五项不可妥协的底线

1. **Gate 0 误触即退**：常规文档检查、代码编写与代码审查直接退出，绝不平庸化滥用。
2. **Gate 1 先顾人再顾事**：察觉你今天累了先接情绪；你说“别烦我写代码”，立刻闭嘴干活。
3. **Gate 2 好想法大方放行**：证据充分、退路容易的好方案直接放行 (PASS)，绝不故意挑刺。
4. **Gate 3 说狠话立字据**：只要打赌，AI 必须写清“出现什么反例算 AI 判断失误”，给 AI 戴上紧箍咒。
5. **Gate 4 否定必须给出路**：指出风险时，必须给出一个低成本尝试的备选方案，绝不只管否定不管解决。

## 🧪 自动化评测与质量保障

驳真拒绝“预打勾的假评测”，自带一套 **27 项自动化可执行评测套件**（Clean-Room 隔离运行，不污染真实台账）：

```bash
# 执行全量自动化测试
npm test
```

- **台账状态机与完整性 (9项)**：验证分母科学剔除、逾期时钟比对、外部干扰强制举证门、防篡改锁定与审计留痕、写后回读双重校验、双向 Markdown 兼容、纪要导出校验与微赌注周期。
- **SSRF 安全防护 (7项)**：验证严格封锁 `127.0.0.1`、`localhost`、`169.254.169.254`（云厂商元数据）、内网私有网段（10/172/192/100.64）与非 HTTP 协议。
- **脑身契约自洽性 (11项)**：静态 Lint 工具，保证 `SKILL.md`、`server.ts`、`evals`、`package.json` 全链路工具名、门禁编号、版本号与战报激励强一致。

> **Adversarial product decision review framework. Stress-test in 30 seconds, settle the score in 30 days.**

- **Two Deployment Modes**: Zero-dependency prompt (`SKILL.md`, ~2.4k tokens) for web/chat, or local deterministic TypeScript MCP server for automated tracking.
